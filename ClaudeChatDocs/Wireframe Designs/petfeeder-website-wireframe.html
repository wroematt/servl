PetFeeder — Website Wireframe

Interactive wireframes for the PetFeeder web application (React / Next.js). Use the left rail to navigate between pages. Click sidebar nav items inside each browser mockup to switch views. The website shares all data with the Android app via the same API, but surfaces more detail and richer data views suited to a larger screen.

React / Next.js Feature parity with app + extras PetFeeder Project · 2026
Persistent left sidebarAll six sections always visible. No hamburger menus — desktop users expect persistent navigation.
Richer data tablesFeed history includes export to CSV. Schedule view is a sortable table. More columns than the app can fit.
Cross-pet statisticsThe Stats page shows all pets together with date-range filters — more powerful than the per-pet app view.
Provisioning is app-onlyThe website shows a setup guide pointing users to the app for BLE provisioning — browser can't access Bluetooth hardware.

Login & registration

The public-facing auth pages. The landing page (not shown) is a marketing page explaining the product. From there, users register or log in. Password reset is email-link based.

Design intent: Auth is centred on a clean card layout. Google Sign-In is offered as a primary option. After first login, users are prompted to either install the app (for device provisioning) or explore the dashboard if they already have the app set up.

Dashboard

The main landing page after login. Combines a quick-feed panel, device status, today's schedule table, and summary metrics in a two-column layout suited to a desktop viewport.

Design intent: The quick-feed panel mirrors the app's Home screen — same meal/snack buttons per pet — so users who switch between platforms have a consistent muscle memory. The device status panel keeps hopper levels visible at all times without needing to navigate to the Devices page. The today's feed table gives a full day view at a glance.

Pets list

A card grid showing all pets. Each card shows the pet's profile photo, type, assigned feeder, today's intake progress, and their three key weights. Clicking a card navigates to the pet detail page.

Design intent: Cards scale well on desktop — two or three per row depending on window width. The progress bar on each card provides an instant visual of today's feeding status. The Add pet button opens a modal rather than a new page, keeping context.

Pet detail

Full profile page for a single pet. Shows weights, today's progress, and a full filterable feed history table with CSV export. Stats for this pet are accessible from a button that navigates to the Statistics page pre-filtered to that pet.

Design intent: The feed history table on this page includes a "Triggered by" column (Schedule / Manual / Voice) — useful for understanding feeding patterns. CSV export is a web-only feature since it's most useful when actioning data further (e.g. pasting into a spreadsheet for a vet visit).

Add pet — modal

Adding a pet on the website uses a centred modal overlay rather than a new page, keeping the pets list visible in the background. The same fields as the app: photo, name, type, weights, feeder assignment.

Design intent: Modal pattern keeps the user oriented — they can see the pets list behind the overlay and know exactly where the new pet will appear on save. The Cat / Dog toggle uses the same pill selector pattern as the app for consistency across platforms.

Statistics

A dedicated statistics page showing all pets together, with date-range filtering. This is richer than the per-pet stats in the app — it allows cross-pet comparison and custom date ranges useful for vet consultations.

Design intent: Two chart panels side by side — one showing a single pet's intake vs target over time, one comparing all pets as a grouped bar chart. The date range filter (Week / Month / Custom) applies to both charts simultaneously. Summary metrics at the top are recalculated on filter change.

Schedule

A full sortable table of all recurring feed schedules. Toggle to enable/disable without deleting. The edit button on each row opens an inline edit form. The Add schedule button opens a modal.

Design intent: The table format lets users see all schedules at once without scrolling, sorting by time or pet. Disabled schedules are shown at reduced opacity with the toggle off. The website schedule view is more scannable than the app's list for households with many scheduled feeds.

Devices

Shows all provisioned feeders with status, hopper level, firmware version, and last-seen time. The "Add feeder" action points to the app since BLE provisioning requires hardware access.

Design intent: Device cards show all the technical detail that doesn't fit well in the app's small hopper graphic — firmware version, last ping time, error log access. The "Add feeder" button opens a modal directing users to the app with a QR code linking to the app store.

Account & household

User profile editing, password change, household member management, and notification preferences. The household section supports inviting new members via a shareable link and setting their role.

Design intent: Account settings live in the sidebar footer — always reachable but not cluttering the main navigation. The household members table shows current members with roles (Owner / Member) and a remove action. Invite is via a shareable link — simpler than email-based invites and works across platforms.
