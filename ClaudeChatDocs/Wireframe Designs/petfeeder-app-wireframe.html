Login & registration

The auth flow covers login, registration, and password reset. On first launch, users are taken here. On subsequent launches, a valid JWT token skips this screen entirely.

Design intent: Keep auth minimal — name, email, password. Google Sign-In should be offered as a one-tap option. Password reset is email-link based. After registration, the user is prompted to add their first pet immediately.

Home — dashboard

The primary screen users land on after login. Designed for the most common daily action: quickly feeding a pet. The quick-feed list is scrollable and scales to any number of pets without layout changes.

Design intent: Meal and snack buttons show the exact gram amount from that pet's profile so users always know what they're dispensing. The low-hopper alert banner appears contextually at the top when any connected feeder is running low. Today's schedule gives a read-only overview without requiring navigation to the Schedule tab.

Pets — list

A card for each pet showing their today's intake vs target. Tapping a card navigates to that pet's full profile. The + button in the top right opens the Add pet flow.

Design intent: The progress tag (e.g. "160g today") gives an instant read on each pet's feeding status. Green = on track, amber = behind, red = significantly under. This lets a multi-pet household see everyone's status at a glance.

Pet profile

The detail view for a single pet. Shows their configured weights, today's progress, and entry points into Statistics and Feed History. The edit button in the top right opens the profile editor.

Design intent: Statistics and Feed History are presented as tappable rows rather than tabs, keeping the profile uncluttered. The "Feed now" button at the bottom is a quick manual dispense shortcut — it will use the pet's meal weight by default but could offer a picker.

Pet statistics

Accessed from a pet's profile. Shows intake vs target over time for that specific pet. Week / Month / All toggle filters the chart range. Back arrow returns to the pet's profile.

Design intent: By scoping stats to one pet at a time (accessed from that pet's profile), the screen stays simple and relevant. A household wanting to compare pets across time can do so on the website's Statistics page which has more screen real estate.

Feed history

A chronological log of every dispense event for a single pet. Shows time, type, and amount. Accessed from the pet profile.

Design intent: Each entry shows the feed type label (Breakfast, Snack, etc.) and timestamp. The amount tag uses a consistent blue colour. Future iterations could add a "triggered by" indicator (schedule vs manual vs voice).

Add pet

A single-page form to create a new pet profile. Photo upload, type selector, weight fields, and feeder assignment. Tapping Save returns to the Pets list with the new pet added.

Design intent: The Cat / Dog type selector uses a toggle-style pill rather than a dropdown — faster to tap and visually clear. Weight fields are numeric inputs; the daily target can be auto-suggested based on pet type and a future weight field. The feeder dropdown only shows feeders already provisioned to this household.

Schedule

All recurring feed schedules across all pets. Each row shows the pet, time, repeat pattern, weight, and an enable/disable toggle. The + button adds a new schedule.

Design intent: Toggles let users temporarily disable a schedule without deleting it — useful for holidays or vet visits. Disabled schedules are visually muted. Swiping left on a row (not shown) would reveal a delete option.

Add schedule

Create a new recurring feed. Select the pet, feed type (Meal / Snack / Custom), time, repeat pattern, and weight. Custom allows entering an arbitrary gram amount.

Design intent: Selecting Meal or Snack auto-populates the weight from the pet's profile, saving the user from re-entering it. Custom clears the weight field for manual entry. The time picker uses the native Android time picker for familiarity.

Devices

Lists all provisioned feeders in the household. Each card shows the feeder name, assigned pet, online status, and a hopper-level indicator. The + button starts the provisioning flow.

Design intent: The hopper graphic gives an immediate visual read of fill level — more intuitive than a percentage alone. Red colouring at low levels draws attention. Tapping a device card would navigate to a device detail screen showing firmware version, error log, and the option to rename or unlink.

Add feeder — provisioning

Guides the user through connecting a new feeder device to their home Wi-Fi. Uses BLE to discover the device, then transfers the Wi-Fi credentials securely to the feeder.

Design intent: The three-step instruction card uses numbered circles to make the sequence unambiguous. Provisioning is app-only (not available on the website) since it requires BLE hardware access. After a successful connection the device appears in the device list automatically.

Settings

User account management, household members, and notification preferences. Accessible via the bell icon in the Home top bar (keeping it off the main nav to preserve the 4-tab limit).

Design intent: Settings is accessed via the notification bell icon on the Home screen rather than a dedicated nav tab. This keeps the bottom nav to 4 items. The household members row opens a sub-screen for inviting and managing users. Sign out is styled in red to prevent accidental taps.
